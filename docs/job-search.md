# 用 Mochi Reader 准备 AI 应用工程师求职

这份文档帮助你把项目变成能说明白、能演示、能继续改进的作品。先运行并理解代码，再根据自己实际完成的工作修改下面的描述；不要直接把自动生成的项目当成已经掌握的经验。

## 简历描述示例

**Mochi Reader｜带证据引用的 AI 技术阅读助手**

基于 Python、FastAPI、SQLite 和浏览器扩展构建技术阅读工具，实现网页文本导入、中文与英文词法处理、BM25 片段检索、DeepSeek 回答、结构化学习卡、自测和 Markdown 导出。提供鲸鱼娘、糯米、学姐三种讲解人设，为回答增加本地引用 ID 检查，提供无需密钥的演示模式和可重复的本地测试与评测。

使用前按实际参与情况改成“独立开发”“参与开发”或“基于开源项目改进”。没有真实 API 测试结果时，不要写模型准确率、上线用户数、调用成本下降比例或性能提升比例。

## 90 秒面试演示

1. **15 秒：问题。** 读技术文档时，普通总结容易丢失依据，读完也难检查自己是否理解。
2. **20 秒：流程。** 导入一段文章，提出具体问题，展示检索结果与回答中的原文依据。
3. **15 秒：学习。** 保存一张知识卡，做一道自测题，再导出 Markdown。
4. **20 秒：实现。** 解释分块、BM25 排序、结构化生成和引用校验分别解决什么问题。
5. **20 秒：边界。** 展示没有证据的问题或错误输入，并说明演示模式与真实模型模式的区别。

## 应该能回答的技术问题

| 面试问题 | 需要实际理解的内容 |
| --- | --- |
| 为什么先做 BM25？ | 它是可解释、无需额外模型服务的词法基线；不能代替语义检索，对同义表达可能失效 |
| 中文怎么检索？ | 查看实际分词代码，解释中文片段与英文词项如何参与打分，能举出成功与失败样例 |
| 分块大小如何影响结果？ | 小块可能丢上下文，大块可能带入噪声；通过固定测试集比较，而不是凭经验声称最优 |
| 引用验证保证什么？ | 检查引用是否存在、原文是否匹配；不能证明整段回答的每个推论都正确 |
| 为什么使用 JSON 输出？ | 让回答、知识卡与题目便于解析；仍需要字段、类型、长度与引用的应用层校验 |
| SSE 解决什么？ | 客户端能逐步接收任务事件；区分任务事件流与模型 token 逐字流 |
| 密钥与网页内容在哪里？ | 密钥配置在本机后端；网页由用户主动导入，真实模型模式会把检索片段发送给配置的提供商 |
| 评测测到了什么？ | 分开解释检索命中、引用结构合法与真实答案质量，给出测试集与执行条件 |
| 模型超时、限流怎么办？ | 指出代码里的超时、错误转换与界面提示；没有实现的重试策略要明确说是计划 |
| 三种角色和三个模型有什么区别？ | 当前角色是共享模型与证据规则的提示词及界面风格，不是分别训练的模型；鲸鱼娘小汐是本项目采用的社区启发设定 |

## 下一轮最有价值的改进

### 做一个能复现的检索对照实验

固定同一批中文、英文和混合技术文档，人工标注每个问题对应的证据片段。保持分块与测试集一致，对比：

1. 当前 BM25 词法基线。
2. 一个真正运行的 embedding 模型加向量检索。
3. BM25 与向量的混合检索。
4. 在相同候选集上增加 reranker 的版本。

记录 Recall@k、MRR、无答案问题的误召回、检索延迟、模型调用量和运行环境。调参集与最终测试集分开，保留失败样例。只有实际测得的数值，才能写进 README 或简历。

### 补真实模型评测

用同一批问题测试回答是否完整、是否受证据支持、是否承认资料不足。记录模型名、时间、提示词版本、请求配置与样本数量。自动评判可以辅助筛选，关键失败样例应人工检查；不要把字符串匹配检查称为事实准确率。

### 做一项你能完整讲解的改进

例如优化中文同义问题召回、为引用增加原文定位、实现文档去重、增加可回滚的索引版本，或加入匿名且可关闭的本地性能统计。保留改动前后的对照数据和一份简短设计记录，比堆叠功能名更有说服力。

也可以增加 [角色一致性评测](characters.md)：同一问题在鲸鱼娘、糯米与学姐风格下，事实、引用和证据不足判断是否一致；鲸鱼娘的短结论、类比与少量角色语气是否真的改善阅读体验。先做真实模型与人工检查，再报告结果，不将三个提示词描述为三个自研人格模型。

## 让项目更容易被看到

- 录一段 30 秒演示：选中文章 → 让鲸鱼娘解释真实问题 → 打开原文依据 → 保存知识卡。第一屏展示角色与用途，明确项目别名和社区启发，不宣传官方联名。
- 用同一个具体案例写中英文 README 和短帖，附安装步骤与真实限制。
- 发布一次清晰的小版本，说明完成的功能、测试方法和已知问题。
- 向相关中文开发者、AI 应用和浏览器扩展社区分享可运行版本，认真回复复现问题；不要群发广告。
- 用真实 issue 和 PR 记录后续改进，不购买 star、不伪造用户、不创建假贡献记录。

求职时优先展示自己能解释的技术决策与失败分析。仓库是否热门，无法替代这些证据。
